# Testing guide

Two suites cover the two halves of the system. Neither re-implements app code
in another language: the JVM suite runs the real Kotlin engine, and the model
suite runs the real `.tflite` file in the TFLite version the APK bundles.

## 1. Sensing engine — 49 JVM tests

```bash
cd PervasiveSense
./gradlew :app:testDebugUnitTest
```

The engine (`SensingEngine` and everything it uses) contains no Android types,
so it runs on a plain JVM. Most tests replay **real** MotionSense recordings
(`app/src/test/resources/fixtures`, generated by `model/export_test_fixtures.py`)
through `deviceEvents()`, which re-delivers a recording the way a phone does:
accelerometer and gyroscope as separate streams at 57.3 Hz and 48.7 Hz with
±2 ms timestamp jitter.

| Class | Tests | What it proves |
|---|---|---|
| `ImuResamplerTest` | 8 | Exact 20 ms grid from off-rate jittered real data, equal to an independent ideal interpolator; waits for the gyro at session start (regression); accel-only fallback; stall → gap, never interpolated across; duplicate/out-of-order events ignored |
| `SlidingWindowTest` | 2 | Oldest-first copy across wrap-around (the model's input layout) |
| `ActivitySmootherTest` | 4 | Immediate first decision; single-window flicker never switches; sustained change switches within 3 inferences; ambiguity never yields a label |
| `ErgonomicPostureTrackerTest` | 5 | Tilt geometry; gravity estimate re-converges within 3 s; fidget separates real sitting/standing from real walking; sedentary timer, break prompt and resets |
| `StepDetectorTest` | 5 | Real walking, jogging and stairs within 10 % of an **independent gyroscope-derived cadence** in 3 orientations (measured error 1–5 %); zero steps sitting/standing; isolated bumps not counted |
| `FallDetectorTest` | 7 | Fall with bounces confirmed 7.5 s after impact; latches until acknowledged; getting up and walking rejects it; upright landing rejected; impact without low-g phase ignored; **no false alarms on any real recording**; gap aborts |
| `RoadAnomalyDetectorTest` | 6 | Pothole and speed breaker detected in 3 phone orientations; 30 s of cabin vibration produces nothing; gated off outside vehicles (incl. real walking); one shock counted once |
| `WellnessScoreEngineTest` | 2 | Composite formula and components; day rollover; state round-trip |
| `ActivityTransitionDetectorTest` | 1 | Only changes are logged, each with its own timestamp |
| `SensingEngineTest` | 9 | End-to-end: real sit→walk→stand stream, first decision ≤ 2.7 s, STILL→WALKING 1.54 s, pipeline adds ≤ 2 inferences, 0.5 s inference cadence, 10 Hz dashboard, correct wellness time and steps; chronological window contract; **model failure surfaces as MODEL_ERROR** (the v1 bug showed a silent UNKNOWN 0 %); eco mode only when still and unobserved; sensor outage never credited; vehicle context and expiry; hardware step deltas incl. reboot; midnight rollover; phones without gyroscope |

The stand-in classifier in `SensingEngineTest` (motion energy of the window)
isolates pipeline timing from model accuracy. Model accuracy and end-to-end
latency *with the real model* are measured by the model suite.

Fall and road-shock scenarios are built from physics because no labelled real
recordings of those events were available; every false-alarm check uses real data.

## 2. Model — 24 tests

```bash
pip install "tensorflow==2.16.1" "keras==3.3.3" pytest
MOTIONSENSE_DIR=<motion-sense/data> UCI_DIR="<UCI HAR Dataset>" pytest -v tests/test_tflite_model.py
```

| Group | What it proves |
|---|---|
| Deployment contract (6) | TF version equals the app's `tensorflow-lite` version; model loads there; `min_runtime_version` metadata ≤ app runtime; app asset byte-identical to the validated model; `[1,128,6] → [1,N]` with N = labels file; Kotlin row-major packing |
| Robustness (2) | Finite, normalised, deterministic output on zeros, saturation and noise; inference < 15 ms |
| Physics (8) | A resting phone is STILL (> 0.9) in all 6 face orientations, the exact reading from the v1 bug report, and 50 random orientations |
| Held-out accuracy (2) | ≥ 95 % accuracy and every class F1 ≥ 0.85 on 15 unseen subjects in random orientations (measured 97.4 %, min F1 0.90); ≥ 93 % prediction agreement under re-orientation (measured ≥ 98.7 %) |
| Streaming (6) | For each unseen MotionSense subject, sit→walk→sit→jog through the app's window/stride/smoothing logic: every switch ≤ 4 s (measured 2.1–3.6 s) and ≥ 95 % correct once settled |

Without dataset paths, 16 tests run and 8 are skipped with a reason.

## Negative controls

A test suite is only useful if it fails on broken code. Checked:

- **v1 model:** fails three independent ways. `min_runtime_version` is 2.17.0 against the app's 2.16.1; the asset hash differs; and loading raises `Didn't find op for builtin opcode 'FULLY_CONNECTED' version '12'`, the on-device failure.
- **Chirality check** for dataset conversion: flipping the gyro sign turns the fitted kinematic sign from +0.963 to −0.966.
- **JUnit runner:** a deliberately failing test is reported as a failure.
- **Android type-check** (used during development against the API 34 `android.jar`): planted mistakes (wrong view ID, non-existent API constant, wrong type) are rejected.
